# Отчёт по производительности (этап 6)

Окружение: headless Chromium (Playwright) без GPU, рендер программный (SwiftShader), окно 1280×720, DPR 1. Сим отдельно — Node 22.

## Сим: шаг на стресс-сцене

`npm run perf`: 300 врагов (неубиваемых), ~1000 снарядов (60% наших с обычным пробитием, 40% вражеских), 6 оружий тира II.

| Версия | мс/тик |
|---|---|
| До оптимизаций (этап 5) | 5.7 |
| `segRect` без аллокаций + отсев по габаритам | 4.1 |
| + кеш прямой видимости (раз в 4 тика) | ≈4.0 |
| + узкие запросы к сетке по фактическому радиусу | 3.0 |
| Финальный честный стресс (пули с пробитием 1) | 2.5–2.7 |

Профиль до: `segRect` — 21% (создавала 4 массива на вызов), сборщик мусора — 7%, `updateBullets` — 27%.

## Рендер: FPS в браузере

| Сцена | Качество | CPU ×1 | CPU ×4 |
|---|---|---|---|
| Старый стресс (бесконечное пробитие), до | высокое | 23.5 | 1.9 |
| Старый стресс, после | высокое | 34.8 | 4.1 |
| Честный стресс 300 врагов / ~400–1000 снарядов | высокое | 36–41 | 6.6 |
| То же | экономия | 48 | 7.8 |
| Реальная волна 18 (≈70–100 врагов, 6 оружий тира III) | высокое | **60** | 20 |

Что сделано в рендере: виньетка заранее отрисована (была градиентом на весь экран каждый кадр), тени врагов — одним путём, вражеские снаряды — пачками по цвету, статичная арена — offscreen-слой (этап 2). «Экономия» дополнительно: без виньетки, DPR 1, без свечения, вдвое меньше частиц.

## Где узкое место

При CPU ×4 на волне 18 JS-часть кадра (сим 2.35 мс + рендер-вызовы 4.9 мс) ≈ 7 мс, а кадр длится ≈ 58 мс: остальное — программная растеризация headless-Chromium. На реальном устройстве растеризация идёт на GPU, поэтому эмуляция занижает результат; **цифры для среднего Android нужно снять на устройстве** (F1 → строка FPS и мс сима/рендера).

Цель ТЗ «60 FPS при 300+ врагах и 1000+ снарядах» на стенде без GPU **не достигнута** (36–48 FPS); бюджет JS (сим ≤ 5 мс) выполнен с запасом.

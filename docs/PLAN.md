# План разработки RIFT RUNNER

После каждого этапа: `npm run build` + `npm test` + ручная проверка в headless Chromium (скриншоты в `docs/screens/`), коммит(ы), короткий отчёт. Коммиты небольшие, по подзадачам.

## Архитектура (фиксируем на этапе 1)

```
src/
  config.ts          // PRODUCT = { name: 'RIFT RUNNER', short: 'RR', version }
  core/              // loop.ts (60 Гц + alpha), input.ts (actions: kb/mouse/gamepad/touch), rng.ts, events.ts, pool.ts, spatial-hash.ts
  sim/               // state.ts (SimState: plain JSON), step.ts, systems/*.ts (movement, ai, weapons, projectiles, damage, pickups, waves, economy), stats.ts, shop.ts, merge.ts
  content/           // weapons.ts, modules.ts, enemies.ts, waves.ts, operators.ts, tags.ts, perks.ts, threat.ts, keywords.ts, balance.ts, arena.ts — типизированные данные
  render/            // renderer.ts (DPR), arena.ts (offscreen), entities.ts, fx.ts (пулы частиц/колец/чисел), glow-cache.ts, camera.ts (trauma)
  ui/                // DOM-оверлеи: menu, hud, shop (терминал), levelup, stats, pause, gameover/victory, settings, devpanel (F1); theme.css
  audio/             // engine.ts, synth.ts (tone/noise из прототипа), bank.ts (SoundBank: id → патч | сэмпл), music.ts (процедурный эмбиент по интенсивности)
  i18n/              // ru.ts (по умолчанию), en.ts, t()
  save/              // meta.ts (версия схемы + миграции), run.ts (снимок SimState между волнами)
tests/               // vitest: stats, armor, merge, shop+luck, wave-gen seed, balance-таблицы, save-migrations
```

Ключевые решения:
- **Сим отделён от рендера**: сим знает только данные и шлёт события (`hit`, `kill`, `hurt`…) в очередь, рендер и аудио их потребляют. Хитстоп — это пауза тиков сима.
- **Сериализуемость**: всё состояние забега лежит в `SimState` без классов и замыканий. Эффекты модулей описываются данными (`{trigger:'onKill', effect:'explode', radius, dmg}`) и исполняются интерпретатором в `sim/effects.ts`. Это и есть основа для сохранения между волнами.
- **Сущности** — массивы структур в пулах (SoA не нужен для 300/1000), удаление swap-remove.

## Этапы

**1. Каркас и паритет** (≈ 6–8 коммитов)
1.1 Vite + TS strict + vitest + eslint, `config.ts`, `legacy/` не трогаем.
1.2 core: loop, rng, input (клавиатура, мышь, тач-джойстик), pool, spatial-hash + тесты.
1.3 sim: перенос прототипа 1:1 (волны «убей всех», 3 пушки с ручным прицелом, перки, рывок, волна, босс каждые 5 волн, ящики).
1.4 render: арена (offscreen), сущности, fx, тряска. Визуально как прототип.
1.5 ui + audio: меню, HUD, пауза, перки, game over, звуки 1:1, i18n-каркас (RU).
1.6 Проверка паритета: скриншоты прототипа и новой версии рядом, чек-лист поведения.

**2. Новая петля боя**
Таймерные волны из `content/waves.ts` · скрап, магнит, бонусный скрап · опыт и уровни, экран «1 из 4» после волны · автоматическое мультиоружие на орбите (6 слотов), выбор ближайшей цели в дальности · ручной режим опцией · единая система статов с источниками · новые враги (сплиттер, минёр, хилер, рой, элиты).

**3. Магазин**
Генерация с удачей и сидом · 4 позиции, реролл, замок, продажа · модули 4 редкостей (40+) с интерпретатором эффектов · слияние I→IV · экран статов с расшифровкой · терминальный UI.

**4. Контент и финал забега**
5 операторов с правилами · синергии тегов 3/6 · Страж Разлома (w10) и финальный босс (w20) с фазами и телеграфами · победа и поражение со статистикой (урон по оружию, причина смерти) · бесконечный режим.

**5. Мета и опции**
Meta-сейв с версией и миграциями · сейв забега между волнами (продолжить) · достижения → открытие операторов · Угроза 1–4 · настройки (громкость музыки и SFX, тряска, вспышки, числа урона, язык, ручной режим, качество) · EN-словарь.

**6. Полировка**
Таблица кривых в `DESIGN.md` (генерируется скриптом из `balance.ts`) · профилирование, стресс-сцена, отчёт FPS · мобильная раскладка портрет и ландшафт · геймпад · процедурный эмбиент · dev-панель F1 (спавн, скрап, предметы, волна, god mode, хитбоксы).

**7. Деплой**
GitHub Actions → GitHub Pages (`base` в Vite) · PWA: manifest, иконки, service worker с версионированием кеша.

## Риски

- Нет реального среднего Android-устройства: FPS проверяю в Chromium с CPU-throttling ×4 и мобильной эмуляцией. Это приближение, на реальном устройстве нужна ваша проверка.
- Объём контента (16 оружий, 40+ модулей, 10 врагов) большой. Держу его в данных и покрываю авто-тестами «цены за эффект», чтобы баланс не расползался.
